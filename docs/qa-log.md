## 第 1 轮 · 立项（2026-10-13）

### 问

想做一个 Web 系统，用来展示相册图集和播放在线音乐：

1. 风格小清新、现代、流畅简约，但看得出精巧美观。
2. 主页是汇总页，有图集和音乐的入口；色调、背景、动画偏艺术小资，给人慵懒放松的感觉。
3. 相册：用类似真实相簿的图标表示每个相册；点击后有推近并打开相簿的动画；可以左右滑动或点击箭头切换图片；点击图片有推近放大的动画，可以缩放、调整角度，关闭后退回相簿。
4. 音乐：类似豆瓣 FM 或网易云网页版；加载硬盘指定目录里的音乐生成播放列表；有转动的封面、播放 / 暂停、音量、切歌；也能播放指定的在线源，外观清爽。
5. 有没有许可证宽松的开源方案？如果没有就自己做。服务器配置一般，要求资源占用少、性能好、速度快。

### 答（要点）

- **开源调研**：没有一个现成项目能同时满足「拟物相簿 + 小清新播放器」。
  - Immich、PhotoPrism 太重（AGPL 许可）；Navidrome 是 GPL 许可，风格也不符；APlayer 老旧；turn.js 不能免费商用。
  - 可以复用的 MIT 组件：PhotoSwipe、StPageFlip、Motion、fast-average-color 等。
- **结论**：自己做设计和交互，具体能力用宽松许可证的组件搭建。
- **初步推荐的技术栈**：Go 后端 + Svelte 前端，打包成一个可执行文件，用 Caddy 提供 HTTPS。
- 列出了 13 个待确认的问题。

## 第 2 轮 · 细节确认（2026-10-13）

### 问（用户的确认）

- 要浅色 / 深色模式，最好还有不同的配色风格；中英文切换。
- 主页显示最近播放、最近打开的照片、播放最多、查看最多，但这块区域要小，不能影响美感。
- 相册名、封面、描述从每个相册目录里的 `about.txt` 读取，没有这个文件就用目录名。
- 相簿像真书一样双页对开翻页；手机竖屏单页，横屏可以双页。
- 旋转可以是任意角度：网页用鼠标拖、手机用手指拖；角度可以加一个合理的限制，用来表示不同的旋转方向。
- EXIF 默认不显示，用一个开关来控制；不要下载按钮。
- 音乐要像车机一样显示内嵌封面和元数据；有歌词文件就显示歌词；功能参考豆瓣 FM、网易云、MusicPlayer2。
- 在线源：参考落雪音乐助手的自定义源，也支持 mp3、m3u8 地址和网络电台；**不接入网易云、QQ 音乐**（有版权风险）。
- 只给自己和家人用，需要密码；主页所有人都能看，相册和音乐需要登录；访客看不到统计信息。
- 一个文件夹就是一个相册；照片和音乐放在不同的目录；每个相册几张到几百张；有 HEIC 和 WebP。
- 需要适配手机。
- 服务器：阿里云突发性能型基础款，1 核 1G。
- 问：方案要不要调整？Go 主要用在哪些领域？Svelte 是什么，和 Vue 有什么区别？

### 答（要点）

**方案调整：**

| 调整 | 原因 |
|---|---|
| 加入 SQLite（纯 Go 版） | 账号、会话、统计、歌单需要持久化 |
| 加入 libvips | 处理 HEIC 和 WebP、自动按 EXIF 方向旋转、读取 EXIF，而且省内存 |
| PhotoSwipe 改成自研查看器 + @use-gesture | 任意角度旋转之后，缩放和拖动的坐标也要跟着变换，PhotoSwipe 不支持 |
| 保留 StPageFlip | 它本身支持宽屏双页、窄屏单页自动切换 |
| 配色 = 配色方案 × 深浅色 | 用 CSS 变量实现 |
| 音源做成插件 | 按风险分级接入：直链、电台 → 免费授权音乐 → 落雪兼容 |
| 针对 1 核 1G | 不在服务器上用 Docker、事先生成多种尺寸的图片、串行处理图片、注意带宽 |

**关于落雪自定义源**：落雪本身不带音源，搜索用的是各平台的接口，自定义源脚本只负责「解析播放地址」，底层来源仍然是酷我、酷狗、QQ、网易云、咪咕等平台，**和「不接入网易云、QQ 音乐」的风险是一样的**。

**Go 简介**：Google 推出的编译型语言，语法简单、并发容易（goroutine）、编译成一个不依赖运行环境的可执行文件。主要领域是云原生和基础设施（Docker、Kubernetes、Caddy 都是用 Go 写的）、后端微服务、网络程序、命令行工具；不擅长桌面界面和机器学习。

**Svelte 简介**：前端组件框架，写法和 Vue 的单文件组件很像。区别在于它是**编译器**：构建时就把组件编译成直接操作 DOM 的 JS，没有虚拟 DOM 的运行时，所以包更小、更快，自带过渡动画。

| | Svelte 5 | Vue 3 | React |
|---|---|---|---|
| 原理 | 构建时编译 | 运行时 + 虚拟 DOM | 运行时 + 虚拟 DOM |
| 体积 | 很小 | 中等 | 较大 |
| 动画 | 自带 | 自带基础过渡 | 依赖第三方库 |
| 生态和就业 | 较小 | 国内很多 | 最多 |

Svelte 5 的 `$state` / `$derived` / `$effect` 大致对应 Vue 的 `ref` / `computed` / `watchEffect`。

## 第 3 轮 · 部署与扩展（2026-10-13）

### 问

1. Go 和 Svelte 开发好、编译出文件后，复制到另一台机器能直接运行吗？还要不要装 Node、Python 这样的运行环境？
2. 播放在线电台和自定义音源时，是不是直接连接到在线源，不消耗阿里云 ECS 的带宽？
3. 以后想做成桌面端，或者像跨平台方案那样一套代码出 App、桌面端和 Web，方案要变吗？

### 答（要点）

**1. 运行环境**

- Go 编译出的是**单个独立的可执行文件**；Svelte 构建出的是静态文件，会用 `go:embed` 打包进这个可执行文件；SQLite 用的是纯 Go 版本。所以服务器上**不需要 Node 和 Go**。
- **唯一例外是 libvips**，需要在服务器上用 `apt install libvips-tools` 装一次。
- 编译时要指定目标平台（`GOOS` / `GOARCH`）。Mac 可以直接交叉编译出 Linux 版本。

**2. 带宽**

- 默认由浏览器直接连接在线源，ECS 只返回几 KB 的数据，**不消耗带宽**。
- 以下情况需要服务器转发，会消耗 ECS 带宽：
  - 音源是 http 地址，而网站是 https（浏览器拦截混合内容）；
  - m3u8 流没有允许跨域访问；
  - 音源有防盗链，需要特定的请求头；
  - 想对在线流用频谱或均衡器。
- 落雪脚本只负责解析出地址，流量很小；音频本身仍然由浏览器直接连接。
- 策略：默认直连，失败后自动改为转发并在界面上提示；转发有签名、有效期和并发上限。

**3. 跨平台**

- 「Web 前端 + 接口后端」本身就是跨平台的基础，不用推倒重来。
- 可选方案：PWA（零改动）；**Wails**（复用 Go 和 Svelte，做 Windows / macOS / Linux 桌面端）；Tauri 2（需要接触 Rust）；Capacitor（手机 App）。不推荐 Flutter 或 React Native，因为界面要重写。
- 现在写代码时就要预留：`apiBase` 可配置、同时支持 Cookie 和 Token 两种鉴权、Go 核心逻辑和启动入口分开、媒体访问做一层抽象。

## 第 4 轮 · 定稿（2026-10-14）

### 问

- ECS 是 **Ubuntu 20.04**。
- 平台只做 **Web + PWA + Windows / macOS 桌面端**，不做 Android / iOS App。
- 文档里要写清架构、方案、使用方法和问答记录，方便回溯和学习。
- 落雪自定义源放到第三阶段，架构上预留接口；最好能做到**只要放入落雪可用的源脚本，整套系统就能直接用**，用于自用和调试。

### 答（要点）

- 选定 **Go + Svelte**。用户希望借这个项目补上这两方面的知识。
- **Ubuntu 20.04**：
  - 标准支持已在 2025 年 5 月结束，但 bailing 不依赖系统库，不受影响；
  - 软件源里的 libvips 8.9 可以解码 HEIC，部署后需要验证；不行就升级系统，或者在 Mac 上先转格式；
  - Caddy 用官方软件源安装（第 5 轮已改为 nginx）。
- **桌面端**选 **Wails**：Go 服务在本机后台运行（免登录），窗口加载同一套 Svelte 界面，媒体文件走本地 HTTP 服务。
- **「放入脚本就能用」的落雪兼容**，需要两部分：
  1. **搜索**：移植落雪内置的 kw、kg、tx、wy、mg 平台搜索代码（Apache-2.0 许可，保留署名）；
  2. **解析**：用 goja 在 Go 里运行脚本，实现 `lx` 全局对象（`request`、`send`、`on`、`utils` 等），并加上沙箱、超时、禁止访问内网地址等限制。
  - 在第一阶段就定义好统一的接口（`TrackRef` / `Playable` / `Searcher` / `Resolver`），以后接入只需要新增代码，不用改动已有部分。
- 生成的文档：`README.md`、`docs/requirements.md`、`docs/design.md`、`docs/architecture.md`、`docs/usage.md`，以及本文件。

## 第 5 轮  补充需求并开始编码（2026-10-15）

### 问

- 如果音乐需要经过服务器加载或转发，要有**明显的提示**，并显示**计时**和**消耗的流量大小**（例如 1024MB），因为服务器按流量计费。
- 用了 Go + Svelte 就需要配置环境，要有**环境配置、修改、调试、打包编译**的指导；Mac 和 Windows 都要有。
- 部署改用 **nginx**，方便和其他 Web 服务一起管理和代理。
- 歌词：目录里有对应歌词文件就加载；没有就**从公共资源下载**后加载；都没有就显示默认提示。

### 答（要点）

- **流量**：
  - 后端最外层中间件统计每一个响应字节，按天、按类别（本地音乐、转发、照片、封面、页面）写入数据库；
  - 每次播放生成一个会话 ID 拼在音频地址上，拖动进度条产生的多次分段请求合并计数；
  - 播放条显示「🖥 服务器传输 3:25 · 8.12 MB」，转发（P2）用强调色闪烁；直连显示「不耗流量」；
  - 设置页有完整的流量面板（今天、本月、分类、30 天柱状图、最近播放明细）；可配置月额度，超过提醒线时顶部出现提示条；
  - nginx 的 `/media/` 必须关闭 `proxy_buffering`，否则 nginx 会预读整首歌，统计偏大。
- **歌词公共资源**：选用 **LRCLIB**（lrclib.net），免费、开放、无需密钥，支持按歌名 + 歌手 + 专辑 + 时长精确匹配，并提供带时间轴的歌词。查找顺序：同名 `.lrc` → 内嵌歌词 → 缓存 → LRCLIB → 默认提示；没找到的 7 天内不重复查询；中文歌覆盖率不如英文歌。
- **nginx**：提供两份模板——独立子域名（`deploy/nginx/bailing.conf`）和挂在已有站点子路径（`bailing-subpath.conf`，需要 `base_path` 和 `BASE_PATH` 构建参数一致）；证书用 certbot。
- **开发指南**：新增 `docs/dev-guide.md`（macOS / Windows 安装、首次启动、代码地图、断点调试、编译参数说明）；Windows 没有 make，提供 `scripts/build.ps1`；VS Code 调试配置放在 `.vscode/`。
- **实现上与原方案的差异**：动画和手势没有引入 Motion、@use-gesture，而是用原生 Web Animations API 和 Pointer Events 实现，减少依赖和体积。
- 第一阶段代码已生成；构建和安装依赖仍由用户本人执行。

## 第 6 轮  首次体验反馈（2026-10-15）

### 问

1. 首页的「最近播放 / 最常播放 / 最近看过 / 最常看过」各显示多少条？
2. 从音乐或相册页回到首页时，默认标签「最近播放」是空的，切换几个标签后才出现内容。
3. 电台、落雪源、歌词下载到音乐同目录，这些是不是还没做？
4. 流量提示只显示当前这首歌的大小，切歌就重新计数，起不到警示作用。希望改成**汇总**：只要经过服务器的流量都累加；关闭再打开页面后重新统计。

### 答（要点）

1. 每个列表最多 **10 条**（接口上限 20），区域固定高度，超出部分在区域内滚动。
2. 原因：便签区默认是折叠的，只有点了标签才会展开；数据也只在打开首页时加载一次。修改后：
   - 默认展开，只记住用户「主动折叠」这一个状态；
   - 每次回到首页、浏览器标签页重新可见、在首页听歌刚计了一次播放时，都会重新拉取。
3. 电台（P2）、直链 / m3u8 / 服务器转发（P2）、落雪自定义源（P3）**确实还没做**，接口已预留（`internal/sources`）。歌词下载**已经实现**，改进如下：
   - `lyrics.save_beside_music` 默认改为开启；
   - 只有纯文本歌词时也会保存；
   - 写入失败（音乐目录没有写权限）时，会在日志里打一条 Warn。
   - 以前已经下载过、只存在缓存里的歌，在歌词面板点一次「重新获取」，就会写出 `.lrc` 文件。
4. 改为**按页面会话汇总**：
   - 每次加载页面，`app.html` 生成一个随机的 `bl_pg` Cookie；后端计量中间件把这个页面收到的**所有字节**累加到同一个计数器（歌曲、转发、照片、封面、页面文件、API）。
   - 播放条上的「本次」芯片显示：经服务器播放的累计时长 · 本页面累计流量。点开可以看到分类明细、页面打开时长、当前这首的流量。
   - 超过设置页的「单页提醒阈值」（默认 500 MB）时芯片变色，超过两倍时闪烁。
   - 刷新或重开页面后从 0 开始统计；按天 / 按月的统计仍然保存在数据库里。

## 第 7 轮  实现第二、三阶段的在线部分（2026-10-15）

**问**：开始实现第二、第三阶段（在线直链、电台、转发、落雪源）。

**答**：后端、前端和文档都已完成。

**1. 服务器转发**（`internal/proxy`、`internal/netguard`）

- 转发链接带 HMAC 签名和有效期，并发数有上限。
- 支持 Range 请求，可以拖动进度条。
- m3u8 播放列表会被逐行改写为转发地址。
- 出站请求拒绝内网和元数据地址，每次重定向都会重新检查。

**2. 直链与电台**

- 直链：mp3、flac、m4a、ogg、m3u8、m3u、pls。
- 电台：按名称、地区、风格浏览 Radio-Browser 目录，支持收藏；直播时禁止拖动进度条。

**3. 直连还是转发**

- 默认由浏览器直连。
- 以下情况改为转发，并显示 ⇄ 提示：混合内容、HLS 不允许跨域、音源需要特殊请求头、直连失败。
- 设置里可以关闭自动转发。

**4. 落雪源**

- 用 goja 运行自定义源脚本，兼容落雪的 `lx` 接口：`request`、`on`、`send`、`utils.crypto`、`buffer`、`zlib`。
- 支持 kw、kg、tx、wy 四个平台的搜索。
- 脚本目录热加载；管理员在设置页上传、停用、删除脚本。
- 音质不支持时自动回退。
- 解析结果缓存 10 分钟。

**5. 其他**

- 在线歌曲的歌词通过 LRCLIB 按「歌名 + 歌手 + 时长」查找。
- 首页「最近播放」里的在线歌曲和电台可以直接再播放。

**需要你在本机执行的命令**（按约定我没有替你安装依赖）：

```bash
cd web_bailing
go get github.com/dop251/goja@latest && go mod tidy
cd web && npm install && cd ..
make lint && make test
```

**已知限制**

- 咪咕（mg）还没有实现搜索。
- 平台搜索接口由平台方控制，可能随时变化。出问题时会在搜索结果区显示错误，脚本解析不受影响。
- 电台收藏和链接历史保存在浏览器本地，换设备后不会同步（歌单功能会统一处理）。

## 第 8 轮  补完第二阶段、拆分发布（2026-10-16）

### 问

1. 电台为什么会消耗服务器流量？不是交给第三方了吗？
2. 为什么要单独提咪咕的搜索？
3. 相册每张图下面留白很多，是 CSS 问题还是留给文字？要不要给每张照片写描述？
4. 做 PWA 和桌面端时，能否把相册和音乐拆开，既能一起发布也能分开发布？
5. 把尚未完成的部分都做完。

### 答（要点）

**1. 电台流量**：Radio-Browser 只是目录，音频由各电台的服务器提供，默认浏览器直连、不耗服务器流量。耗流量的情况主要是「混合内容」：网站是 https，而很多电台只有 http 地址，浏览器会拦截，只能由服务器转发。改进：先尝试同一地址的 https 直连，9 秒内不行才转发；电台列表新增「只看 https 电台」；`http` 电台有小标签提示；仍可在设置里关闭自动转发。

**2. 咪咕**：落雪的源脚本只负责解析播放地址，搜索要为每个平台单独实现。咪咕的搜索接口需要签名，当时没做。现在已实现并实测通过。

**3. 相册留白**：是排版计算造成的（每页按 3:4 纸张计算，照片最多只占 78%×70% 并居中，横拍照片在竖页上只占约 44% 的高度），不是给文字留的位置。按你的决定**不增加每张照片的描述**，只保留 about.txt 描述相簿。调整为：

- 保持原照片比例，可用区域放大到页宽 88%、页高 80%；
- 两张相邻的横拍照片拼在同一页（上下排列，各占页高约 37%），竖拍照片一页一张；
- 页码按「页」计，顶部的「第 a / b 张」显示当前页第一张照片的序号。

**4. 拆分发布**：可以。构建时用 `APP=all|photos|music` 选择版本（导航、首页、PWA 名称和图标、桌面端都随之变化）；服务器用 `features` 开关决定运行哪一部分。两者同时生效。

**5. 新完成的功能**：

- 收藏与歌单（服务器保存、跨设备）：歌曲、在线歌曲、电台都能收藏和加入歌单；「音乐 → 我的」统一管理；
- 播放速度、定时停止（含「放完这首」和渐弱）、10 段均衡器（8 个预设）、频谱；
- PWA：可安装，只缓存应用外壳，有新版本时提示刷新；
- Wails 桌面端：内置本地服务、免登录，三个版本各自独立；也可以设置远程模式；
- 咪咕搜索。

**均衡器和频谱的限制**：浏览器只允许读取同源或允许跨域（CORS）的音频数据。本地音乐不受影响；不允许跨域的在线歌曲和电台在打开音效后会改走服务器转发（有提示）；关闭音效后要刷新页面才会恢复直连。

**需要你在本机执行的命令**（按约定我没有替你安装依赖）：

```bash
# 桌面端（只在需要构建桌面版时）
go install github.com/wailsapp/wails/v2/cmd/wails@latest
make desktop-deps            # = cd desktop && go get github.com/wailsapp/wails/v2@latest && go mod tidy
make desktop APP=all         # 或 APP=photos / APP=music
```

服务器和网页部分不需要新依赖：`make lint && make test` 即可。
